## [0.1.9] - 2026-09-04

### Added
- `tests/schema_input_drift_gate.rs`: every `docs/schemas/<cmd>.schema.json` must describe the same INPUT surface `schema --cmd` publishes. The capability existed as `scripts/generate_command_schemas.sh --check`, which `cargo test` never runs, so the files went stale in silence: `config.schema.json` listed neither `user_data_dir` nor `input_typo_permille`, both of which had reached the binary, `config list-keys` and `docs/CONFIGURATION.md`. The gate compares `properties` and `required` only — a whole-document comparison makes all 72 files diverge on envelope alone, which measures the instrument rather than the artifact. Live gate count 88 to 89.
- `tests/screen_source_doc_gate.rs`: every token `screen_source` can emit must be named in `docs/COOKBOOK.md` and `docs/COOKBOOK.pt-BR.md`. The gate reads `ScreenSource::ALL`, so it cannot fall behind the enum the way a copied list would. `screen_source` is an OUTPUT contract and the schemas describe only the `--screen` INPUT, so until now the token set had no owner in any live document: the sole enumeration lived in `gaps.md`, which `doc_binary_numeral_gate` excludes on purpose as a dated audit log. Live gate count 87 to 88.
- `screen_source` and its five tokens documented in both cookbooks, including what `floor` means for a caller who reads only the number.
- `input_typo_permille` XDG key: chance in a thousand that a character is typed wrong, erased with `Backspace` and retyped, so the field still ends up holding exactly the requested text. `0` by default, and the only humanisation key that is: every other one disperses TIMING, which a page cannot read as a different value, while this one changes the CHARACTER STREAM an `input` listener sees. The wrong key is always a physical neighbour on the QWERTY row. Live key count 216 to 217.
- Per-bigram typing speed in `src/native/interaction/kinematics/qwerty.rs`: the gap between two characters now scales with the QWERTY finger pair, so `th` (alternating hands) is faster than `qz` (one finger, two rows). Derived from the layout rather than copied from a digraph table, because a table measures one corpus while the finger pair is the cause behind it. No knob: there is no value an operator could sensibly choose differently.
- `tests/csp_init_script_gate.rs`: proves that a page publishing `Content-Security-Policy: script-src 'none'` does not reach the stealth payload. It exists because the row it backs cites no line of this tree — it rests on a behaviour of Chrome, and a claim with no code behind it has nothing that can fail when it stops being true.
- `user_data_dir` XDG key: a persistent Chrome profile, opt-in and unset by default. Unset is what keeps residual-zero true for every caller who did not ask; setting it deliberately trades that invariant away, because a detector that attests SESSION cannot be satisfied by one-shot processes that each present as a different machine. Created with mode 0700 on Unix. `--profile` on argv still wins. Live key count 215 to 216.
- `runtime_enable_used` in the policy witness, so the claim that the default launch no longer enables the `Runtime` domain is checkable from outside rather than taken on the word of a comment.
- `serp_endpoint` in the `search` envelope, reporting `known` or `unknown` for the configured `search_base_url`. Published on the failure envelope too, under `data` alongside `search_base_url`, so an unknown endpoint is distinguishable from an empty web.
- `tests/doc_binary_numeral_gate.rs`: every configuration-key count published in live prose is compared against `config list-keys`. `CHANGELOG` and `gaps.md` are excluded because a dated measurement is history. It found four sites in `docs/MIGRATION*` still claiming 206 that a manual sweep for the previous figure could not have found.
- `tests/bilingual_flag_parity_gate.rs`: every translated document pair must enumerate the same long flags. It found twenty-seven asymmetries on its first run, two of them with the ENGLISH side deficient, a direction no earlier audit had supposed possible.
- The error envelope carries `retryable`. It already told an agent `kind`, `message`, `exit_code` and `suggestion`, and left the one decision an agent actually has to make — try again or route around — to be guessed from prose. Derived from the message rather than the kind, because the kind is too coarse: `unavailable` covers both "chrome is not installed", which no amount of retrying fixes, and "connection reset", which is exactly what a retry is for. Emitted unconditionally, `false` included, for the reason `scrape_local::disclosure` already states about its own fields — a key that appears only when true is indistinguishable from a key that was never implemented
- `scrape` discloses `transport_fingerprint`, on BOTH engines. `tls_impersonation: false` said the JA3 had not been forged and left open what it actually was, so a caller correlating a block against a fingerprint database had to guess the library. The `http` engine reports `rustls` and the `browser` engine `chrome-boringssl`; emitting it on only one would have created a key that cannot be filtered on, which is the defect that module exists to prevent
- `scripts/supply-chain-check.sh` runs `cargo audit` and then `cargo deny check`. Twenty-nine verifiers measured this repository and not one read a dependency advisory, so that debt was invisible by construction and surfaced only when a human thought to ask. The two are not redundant and the order is not arbitrary: `cargo audit` asks about the LOCKFILE and `cargo deny` about the RESOLVED GRAPH, which is why the second one stayed silent about `paste` and `proc-macro-error2` — both are written in `Cargo.lock` and neither is in the graph. The difference between the two lists is therefore a stale-lockfile detector for free. The verdict comes from the exit code and never from parsing, so a transitive advisory warns and only a vulnerability fails: a gate that fails for a debt the operator cannot pay is a gate the first person to hit it switches off, and switched off it no longer sees the vulnerability either
- `--headless` and `--browser-mode <auto|headless|headed>` join `--headed`, so every window mode is reachable from argv. Until now headless was obtainable only by asking for nothing, which made "I require headless" and "I said nothing" the same command line — and a requirement that cannot be expressed cannot be verified. Callers worked around it by stripping `DISPLAY` from the environment, a defence by absence that protects only the paths someone remembered to strip. The three spellings are mutually exclusive and the parser refuses more than one, so the conflict costs exit 2 and never a surprising launch
- The resolved window mode now records WHICH precedence step chose it. `PolicySource` moved out of `stealth.rs`, where it had been describing `--stealth-profile` alone, into a shared module: the three steps it names are the same three every policy here resolves through, and keeping it private to one policy is what let `stealth_profile` be able to state its provenance while `browser_mode` — the decision with a security consequence — could not
- `docs/COOKBOOK.md` has a recipe for `sitemap` and `feed`, in both languages. Both verbs were already in the file's flat inventory and neither had an executable line, which is the same defect one layer up from the one they were added to close: a name in a list that no prose explains. The gap was invisible to a keyword sweep because `--use-sitemap`, a flag of `map`, matches `sitemap`
