# browser-automation-cli

> CLI one-shot de automação Chrome CDP para agentes de IA, sem daemon e sem telemetria remota.

browser-automation-cli é uma CLI Rust de processo único que lança Chrome ou Chromium do sistema via CDP, executa ações de browser do agente e depois finaliza e sai. Ciclo de vida: BORN, EXECUTE, FINALIZE, DIE. Settings de produto usam flags da CLI e comandos XDG `config` apenas.

## Superfície de Comandos (v0.1.8)
- Inventário completo (**69** nomes via `commands --json`, ordenados): assert, attr, audio, back, batch-scrape, click-at, commands, completions, config, console, cookie, crawl, devtools3p, dialog, doctor, drag, emulate, eval, exec, extension, extract, fill-form, find-paths, forward, goto, grab, heap, hover, image, keys, lighthouse, locale, man, map, mitm, monitor, net, page, parse, perf, pick, press, print-pdf, qr, record, reload, resize, run, schema, scrape, screencast, scroll, search, select-option, sg-rewrite, sg-scan, sheet-write, storage, submit, text, type, upload, version, video, view, wait, webmcp, workflow, write
- Descoberta: doctor (browsers_dir, origem lighthouse, cache_redis, residual_disk + JSON residual), commands, schema (`schema <cmd>` ou `schema --cmd`), version, locale, man, completions
- Flags globais: **56** flags longas no help global, sendo **54** de produto mais `--help` e `--version`; fonte da verdade é `browser-automation-cli --help`
- Config XDG: config init|path|show|get|set|unset|list-keys (`config unset <KEY>` restaura uma chave ao default embutido; descubra todas as chaves com `config list-keys --json`)
- Stealth: ligado por padrão; `--no-stealth` desliga os patches anti-detecção nesta execução; `--stealth-profile auto|chrome-linux|chrome-win|chrome-mac` escolhe a identidade personificada; `--stealth-seed <SEED>` fixa a identidade entre processos, para que um crawl de N URLs em N processos one-shot não se apresente como N máquinas
- Proxy: `--proxy <URL>` (`http`, `https`, `socks5`) roteia o Chrome e o motor HTTP; `--proxy-bypass <HOSTS>` lista os hosts que ignoram o proxy, na sintaxe de bypass-list do Chrome
- Input humano: `--input-profile human|direct` (padrão `human`) interpola trajetórias do ponteiro, aplica dwell entre press e release e ritma a digitação; `--input-seed <SEED>` semeia o jitter de input para reprodutibilidade
- Modelagem de sessão: `--warmup` e `--warmup-url <URL>` aquecem a sessão antes da URL alvo; `--no-xvfb` pula o display virtual privado no Linux
- Afirmações de payload: `--expect <EXPR>` afirma `key=value`, `key!=value` ou `key~substring`, repetível e conjugado por AND; `--expect-exit-code` sai com 65 quando algum `--expect` falha
- Navegação: goto, back, forward, reload (CDP Page.reload + ignoreCache; `--handle-before-unload accept|dismiss`)
- Scrape: scrape (--format/--formats multi/CSV; --engine http|browser; format/formats no run), batch-scrape, crawl, map, search (limpa uddg), parse (PDF/DOCX/xlsx/ods, --redact-pii)
- Interação: view, press, write, type, keys, wait (multi --text OR; url/url_contains/navigation/wait_timeout_ms no run), hover, drag, fill-form, select-option, pick (select nativo + HIG), submit, upload, click-at
- Observação: extract (--llm/--question/--schema-json), text, scroll (dy/dx no run), attr, assert, grab (png|jpeg|webp apenas; AVIF removido)
- Abas/Diálogos: page, dialog accept|dismiss (`.data.dialog_settled`; isolamento multi-aba por session_id; --if-present), cookie, storage
- Captura/utils: console, net, print-pdf, monitor, qr, find-paths, sheet-write, sg-scan, sg-rewrite
- Observabilidade de rede: `--capture-network` no MESMO processo, depois `net list` (--page-idx, --page-size, --resource-types, --include-preserved) e `net get <IDX>` (--request-path, --response-path)
- Mídia local one-shot (sem Chrome): image info|convert|resize|download|exif, video info|download|convert|to-mp3|trim|thumbnail|manifest, audio info|download|convert|trim
- Avançado: eval, emulate, resize, perf, lighthouse (flag→XDG→PATH; fixtures unitárias com LHR 13.4.1 capturado; e2e mock SKIP), screencast, heap, extension, devtools3p, webmcp, mitm, workflow, run, exec, record --url --path (--seconds padrão 30, --max-events padrão 200; grava NDJSON reproduzível por `run --script`)
- Multi-passo via stdin: `run --script -` lê passos NDJSON do stdin, um por linha, contra uma única sessão viva
- Modo stdin valida cada linha ao chegar (`validation: "per-line"`); EOF dispara o FINALIZE
- Prefira stdin a process substitution do shell: `run --script <(printf ...)` é recusado pelo jail de arquivos
- Residual-zero de disco (0.1.5 RES-01…12 ainda verdadeiro): BORN auto-GC Singleton-only em `/tmp` (piso 60s); FINALIZE dual scavenge + re-scan; nunca mata Chrome Flatpak do host
- Residual intencional: GAP-022 ~53 dups; GAP-023/024 divergências de PRD
- Ciclo de vida: BORN, EXECUTE, FINALIZE, DIE; product law residual-zero de processo + disco

## Contrato de Settings
- Settings de produto: flags da CLI + XDG via `config path|init|show|set|get|list-keys` apenas
- Chaves importantes: dialog_settle_ms, chrome_path, lighthouse_path, openrouter_api_key, llm_*, cache_backend, cache_redis_url, lang, log_level, stealth, stealth_profile, stealth_seed, browser_mode, input_profile, proxy_url, proxy_bypass, proxy_username, proxy_password, http2_enabled, robots_user_agent, scrape_no_cache — referência completa com todas as **204** chaves em `docs/CONFIGURATION.pt-BR.md`; legível por máquina via `config list-keys --json`
- Restaurar um default: `config unset <KEY>` é o inverso de `set`; `config set <key> ""` NÃO é o inverso, porque para chave string grava um vazio que o caminho normal nunca produz e para chave numérica é erro de parse
- Credenciais de proxy: `proxy_username` e `proxy_password` vão SOMENTE no XDG, nunca em argv, porque a tabela de processos expõe argv
- Logging: `--verbose`/`--debug`/`-q` ou `config set log_level` / `log_to_file`
- Cor: `config set color true|false`
- Chrome / Lighthouse: path do shell ou `config set chrome_path|lighthouse_path` (lighthouse também por flag)
- Settle de diálogo: `config set dialog_settle_ms`; leia `.data.dialog_settled` após dialog accept|dismiss
- Cache Redis: `config set cache_backend redis` + `cache_redis_url` (somente `redis://`; `rediss://` fail-closed)
- Lang: `--lang pt-BR` ou `config set lang` localiza sugestões
